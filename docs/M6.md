## Lighthouse – testovací stránka hostitele

`pnpm --filter @sauna/e2e lighthouse` (= `node e2e/lighthouse.mjs`). Lighthouse 13, mobil, simulované škrcení, medián ze 3 běhů.
Porovnává 3 varianty stejné stránky (`apps/embed/demo/host.html`):

- `baseline`: stránka bez snippetu;
- `embed`: konfigurátor pod ohybem stránky (obvyklé umístění);
- `embedTop`: konfigurátor hned nahoře.

Limit je pokles nejvýš o 5 bodů v každé kategorii.

| Varianta | Performance | Accessibility | Best practices | SEO | LCP | CLS | Přeneseno |
|---|---|---|---|---|---|---|---|
| baseline | 100 | 100 | 100 | 82 | 0,63 s | 0 | 1 kB |
| embed | 100 | 100 | 100 | 82 | 1,21 s | 0 | 25 kB |
| embedTop | 100 | 100 | 100 | 82 | 1,36 s | 0 | 253 kB |

**Pokles: 0 bodů.** SEO 82 platí pro všechny tři varianty. Jde o vlastnost testovací stránky (chybí meta description apod.),
ne o vliv konfigurátoru.

Úvodní měření `embedTop` dalo performance 77 kvůli CLS 0,65: prázdný kontejner měl výšku 0, dokud se nenačetl async `embed.js`.
Oprava je popsaná v D-054:

1. `embed.js` hned rezervuje odhadovanou výšku.
2. Konfigurátor posílá výšku až po prvním vykreslení.
3. Snippet má volitelný řádek `<style>`, který místo rezervuje ještě před spuštěním skriptu.

Reporty: `docs/m6/lighthouse-*.html`, souhrn: `docs/m6/lighthouse-results.json`.

## Izolace tenantů

`apps/api/test/isolation.test.ts`, 21 testů. Běží na PGlite i na skutečném PostgreSQL (`TEST_DATABASE_URL`).

Tenant A (demo) má konfiguraci, poptávku s fotkou a vygenerované soubory. Tenant B (`other`) zkouší přistoupit k datům A:

- **Veřejné routy:** `?tenant=other` s id konfigurace z A vrátí 404.
- **Poptávka:** poptávka pro B s id konfigurace z A založí novou konfiguraci. Revize A zůstane 1.
- **Admin routy:** session B s id z A vrátí 404 u seznamu, detailu, změny stavu, 5 exportů, verze katalogu `demo-1` i XLSX.
  Soubory A vrátí B také 404.
- **Seznamy:** B vidí jen svá data. Stav poptávky A se nezmění.
- **Katalog:** když B publikuje katalog s `tenantId: 'demo'`, vznikne verze `other-…` a A zůstane beze změny.
- **Integrita:** v žádné tabulce není řádek s `tenant_id IS NULL`.

Dál platí D-055: konfigurátor ve vloženém iframe kontroluje `embedOrigins` tenanta.

## Docker Compose

```sh
docker compose up --build
```

| Služba | Adresa | Obsah |
|---|---|---|
| web (nginx) | http://localhost:8080/ | testovací stránka hostitele s embedem |
| | http://localhost:8080/configurator/ | konfigurátor (samostatně) |
| | http://localhost:8080/admin/ | administrace (`admin@demo-sauny.example`, výrobce `demo`) |
| api | http://localhost:3000/health | Fastify + worker, PDF přes Chromium v image Playwright |
| mailpit | http://localhost:8025/ | zachycené e-maily (magic link, poptávky) |
| db | – | PostgreSQL 16, svazek `dbdata` |

- `docker/api.Dockerfile` vychází z `mcr.microsoft.com/playwright:v1.55.0-noble` (stejná verze jako `playwright-core`) a běží
  pod uživatelem `pwuser`. `CHROMIUM_PATH=""` vybere Chromium přibalené v image. Při prvním startu se spustí migrace a seed
  (`SEED_DEMO=1`).
- `docker/web.Dockerfile` sestaví `embed.js`, konfigurátor a admin s `VITE_API_BASE` a servíruje je přes nginx (gzip,
  immutable cache pro `/assets/`, CORS na `embed.js`). Admin má `X-Frame-Options: DENY` a `frame-ancestors 'none'`.
- Proměnné jsou v `docker-compose.yml`. Pro produkci se přepíšou URL, `SMTP_URL` a heslo databáze (žádné tajné klíče v repu).

**Výhrada:** v tomto prostředí není Docker daemon. Ověřil jsem jen `docker compose config` (platná konfigurace) a všechny
kroky sestavení zvlášť: `pnpm build`, API s `CHROMIUM_PATH=""`, migrace na PostgreSQL 16. Samotné sestavení image a spuštění
compose je potřeba ověřit na stroji s Dockerem.

## CI

`.github/workflows/ci.yml`:

1. `pnpm typecheck`.
2. `pnpm test` (PGlite).
3. Testy API znovu na PostgreSQL 16 (service container).
4. `pnpm build`.

Pro PDF v testech API se instaluje Chromium přes Playwright. Prohlížečové e2e (`pnpm e2e`, Lighthouse, full-flow) se v CI
zatím nespouští, běží lokálně.

## Další opravy v M6

- Three.js r186 už nemá `PCFSoftShadowMap`. Viewer používá `PCFShadowMap` (bez varování v konzoli).
- Testovací helpery API berou `CHROMIUM_PATH` z prostředí.
- Klik na opravu v seznamu upozornění se v e2e opakuje, dokud se oprava neprojeví, protože seznam se po každém výpočtu
  překresluje.
